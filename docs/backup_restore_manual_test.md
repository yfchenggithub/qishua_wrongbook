# 备份恢复手工测试清单

## 前置准备
1. 使用 Android Dev Client 安装并打开 App。
2. 进入“设置 > 数据备份与恢复”。
3. 确认设备可以打开系统分享面板与文件选择器。

## 场景 1：空数据备份恢复
1. 保证当前没有错题、图片、复做记录。
2. 点击“备份到文件”，确认开始备份，完成后走系统分享保存备份文件。
3. 回到设置页，点击“从备份文件恢复”，选择刚保存的 `.qsbk`。
4. 在预览弹窗核对数量均为 0，点击“确认恢复”。
5. 预期结果：提示“恢复完成”，首页与错题列表仍为空，App 无报错。

## 场景 2：普通错题 + 图片 + 复做记录备份恢复
1. 新增至少 2 道错题，每道包含题目图、答案图；完成至少 1 次复做。
2. 执行“备份到文件”，保存备份文件。
3. 手动再新增 1 道错题（用于验证恢复覆盖）。
4. 选择刚才备份文件并确认恢复。
5. 预期结果：恢复后数据与备份时一致，后加的那道题被覆盖掉；首页任务与错题列表刷新正确。

## 场景 3：图片缺失时备份
1. 准备至少 1 条带图片的错题数据。
2. 在设备文件管理器中手动删除其中一张已保存图片（仅删文件，不删记录）。
3. 执行“备份到文件”。
4. 预期结果：备份仍成功；恢复预览时可看到该备份有图片缺失提示；App 不崩溃。

## 场景 4：选择错误文件
1. 点击“从备份文件恢复”并选择一个非 `.qsbk` 文件或任意无关文件。
2. 预期结果：弹窗提示“备份文件格式不正确”或对应可读错误；当前数据不变。

## 场景 5：恢复中模拟失败
1. 先准备一个可用备份文件。
2. 手动破坏备份包（例如把 `data.json` 改坏后重新打包为 `.qsbk`）。
3. 执行恢复并确认。
4. 预期结果：出现“恢复失败”弹窗；当前数据尽量保持不变；恢复前安全备份已保留。

## 场景 6：恢复后首页今日任务刷新
1. 备份 A：包含“今天有待复做题”。
2. 备份 B：包含“今天无待复做题”。
3. 先恢复 A，再恢复 B。
4. 预期结果：首页“今日任务”数量随恢复结果变化并及时刷新。

## 场景 7：恢复后错题详情图片显示
1. 用含多张图片（题目图、答案图、复做图）的备份执行恢复。
2. 打开对应错题详情页。
3. 预期结果：图片能正常显示，顺序正确，复做图片关联正确。

## 日志核对（每个场景都建议查看）
1. 打开设置页日志入口。
2. 重点检查备份日志：`backup_start`、`backup_collect_db_done`、`backup_collect_images_done`、`backup_package_created`、`backup_share_opened`、`backup_failed`。
3. 重点检查恢复日志：`restore_pick_file`、`restore_inspect_start`、`restore_inspect_done`、`before_restore_backup_start`、`before_restore_backup_done`、`restore_extract_done`、`restore_db_transaction_start`、`restore_db_transaction_done`、`restore_success`、`restore_failed`。
