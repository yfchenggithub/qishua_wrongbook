# 备份恢复手工测试清单

## V10 自动化专项检查

每次修改模块、编号或备份恢复逻辑后，先在项目根目录运行：

```powershell
npm run check:backup-v10
```

检查通过表示以下数据库契约仍然成立：

- V10 备份包含永久 `module_id`、模块内 `question_no`、完整 `modules` 和 `moduleQuestionCounters`。
- 系统模块和自定义模块通过永久 `module_id` 恢复关联。
- 模块题号计数器恢复后继续递增，已经领取但对应错题已删除的编号不会复用。
- 系统模块与自定义模块拥有互相独立的题号序列。

该脚本使用内存 SQLite 验证数据库契约，不替代 Android 真机上的 `.qsbk` 文件、图片、语音、系统分享面板和文件选择器测试。

## 前置准备
1. 使用 Android Dev Client 安装并打开 App。
2. 进入“设置 > 数据备份与恢复”。
3. 确认设备可以打开系统分享面板与文件选择器。
4. 首次没有当天备份时，打开 App 后应立即开始自动备份，不需要先退到后台。
5. 备份完成后设置页应自动显示“今日已自动备份”，按钮变为可用的“分享/导出”。

## 场景 1：空数据备份恢复
1. 保证当前没有错题、图片、复做记录。
2. 启动 App 并等待当天自动备份完成；点击“分享/导出”，通过系统面板保存备份文件。
3. 回到设置页，点击“从备份文件恢复”，选择刚保存的 `.qsbk`。
4. 在预览弹窗核对数量均为 0，点击“确认恢复”。
5. 预期结果：提示“恢复完成”，首页与错题列表仍为空，App 无报错。

## 场景 2：普通错题 + 图片 + 复做记录备份恢复
1. 新增至少 2 道错题，每道包含题目图、答案图；完成至少 1 次复做。
2. 在下一个本地自然日启动或唤醒 App，等待自动备份完成后点击“分享/导出”保存备份文件。
3. 手动再新增 1 道错题（用于验证恢复覆盖）。
4. 选择刚才备份文件并确认恢复。
5. 预期结果：恢复后数据与备份时一致，后加的那道题被覆盖掉；首页任务与错题列表刷新正确。

## 场景 3：图片缺失时备份
1. 准备至少 1 条带图片的错题数据。
2. 在设备文件管理器中手动删除其中一张已保存图片（仅删文件，不删记录）。
3. 清除当天自动备份测试文件或在下一个本地自然日触发自动备份。
4. 预期结果：备份仍成功；恢复预览时可看到该备份有图片缺失提示；App 不崩溃。

## 场景 4：选择错误文件
1. 点击“从备份文件恢复”并选择一个非 `.qsbk` 文件或任意无关文件。
2. 预期结果：弹窗提示“备份文件格式不正确”或对应可读错误；当前数据不变。

## 场景 5：恢复中模拟失败
1. 先准备一个可用备份文件。
2. 手动破坏备份包（例如把 `data.json` 改坏后重新打包为 `.qsbk`）。
3. 执行恢复并确认。
4. 预期结果：出现“恢复失败”弹窗；当前数据尽量保持不变；恢复前安全备份已保留。

## 场景 6：恢复后首页今日任务刷新
1. 备份 A：包含“今天有待复做题”。
2. 备份 B：包含“今天无待复做题”。
3. 先恢复 A，再恢复 B。
4. 预期结果：首页“今日任务”数量随恢复结果变化并及时刷新。

## 场景 7：恢复后错题详情图片显示
1. 用含多张图片（题目图、答案图、复做图）的备份执行恢复。
2. 打开对应错题详情页。
3. 预期结果：图片能正常显示，顺序正确，复做图片关联正确。

## 场景 8：自定义模块与自定义错因备份恢复
1. 在新增错题页分别新增 1 个自定义模块和 1 个自定义错因，并用它们保存 1 道错题。
2. 在下一个本地自然日启动或唤醒 App，等待自动备份完成后通过“分享/导出”保存备份文件。
3. 回到 App 删除或改名刚才的自定义模块、自定义错因，再新增 1 个不在备份里的自定义配置。
4. 选择刚才备份文件并确认恢复。
5. 预期结果：恢复后自定义模块、自定义错因回到备份时状态；第 3 步后加或改的自定义配置被覆盖；对应错题详情里的模块和错因名称正确。

## 场景 9：跨日自动轮换
1. 准备一份昨天日期的自动备份测试文件，并确保自动备份目录中没有今天的备份。
2. 启动 App 并保持前台，不等待 Android 后台任务。
3. 预期结果：立即生成今天的 1 份自动备份；昨天及更早的自动备份被删除。
4. 再准备一次测试后，将 App 切到后台。
5. 预期结果：已开始的备份继续执行，不会因为前后台切换而取消。
6. 再次进入设置页或重复触发运行时/后台任务。
7. 预期结果：不会重复生成第二份今天的备份，设置页仍分享/导出同一文件。

## 场景 10：V10 模块编号与计数器恢复

1. 在“函数”模块连续新增两道错题，确认编号依次为 `A001`、`A002`。
2. 删除 `A002`，保留 `A001`；删除后不要再向“函数”模块新增错题。
3. 新增一个自定义模块并录入一道错题，确认该模块编号为 `U016` 或当前实际分配的 `Uxxx`，错题编号为 `Uxxx-001`。
4. 记录该系统模块和自定义模块的名称、显示编号；在开发数据库页同时记录两道题的数字 `module_id`、`question_no` 和对应计数器值。
5. 确保上述数据创建后重新生成一份自动备份，再通过“分享/导出”保存 `.qsbk` 文件。若当天已有旧自动备份，应先清除测试备份或在下一个本地自然日重新触发。
6. 备份完成后，修改自定义模块名称，并分别向“函数”和该自定义模块新增一道错题，制造与备份内容不同的本机状态。
7. 从第 5 步的 `.qsbk` 文件恢复，确认恢复完成且没有进入回滚。
8. 预期结果：`A001` 与 `Uxxx-001` 均存在，恢复后显示编号与备份时一致；第 6 步新增的两道错题消失，自定义模块名称恢复为备份时名称。
9. 在开发数据库页核对：两道题仍关联备份时记录的永久数字 `module_id`；“函数”计数器仍为 `2`，自定义模块计数器仍为 `1`。
10. 恢复后分别向“函数”和该自定义模块新增一道错题。
11. 最终预期：“函数”新题编号为 `A003`，不得复用已删除的 `A002`；自定义模块新题编号为 `Uxxx-002`，两个模块的计数器互不影响。
12. 再次打开原有两道题详情，确认模块名称、显示编号和题目内容均正确。

## 日志核对（每个场景都建议查看）
1. 打开设置页日志入口。
2. 重点检查备份日志：`backup_start`、`backup_collect_db_done`、`backup_collect_images_done`、`backup_package_created`、`backup_share_opened`、`backup_failed`。
3. 重点检查恢复日志：`restore_pick_file`、`restore_inspect_start`、`restore_inspect_done`、`before_restore_backup_start`、`before_restore_backup_done`、`restore_extract_done`、`restore_db_transaction_start`、`restore_db_transaction_done`、`restore_success`、`restore_failed`。
