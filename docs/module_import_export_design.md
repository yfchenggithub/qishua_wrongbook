# 七刷错题本模块导入导出设计（V1）

## 1. 文档状态

- 当前阶段：V1 按服务层分步实现。
- 已实现题包 TypeScript 契约与校验器、导入来源持久化、只读导出数据映射、`.qsm` 归档生成、正式导入服务，以及包含文件选择、预览、确认、进度和结果反馈的导入页面。
- 尚未实现导出页面和系统分享。
- 后续实现数据库变更前，必须先同步更新 `docs/data_contract.md`。
- 本功能完全离线，不引入登录、云同步、题包市场或服务器接口。

## 2. 功能定义

“模块导入导出”是一套用于分享优质错题内容的独立能力。用户可以把一个模块中的题目、答案、解析、标签和图片导出为单个文件，其他用户再把该文件导入自己的错题本。

本功能在产品中统一称为“题包导入/导出”；文件中的内容单位称为“模块包”。

### 2.1 与备份恢复的区别

| 对比项 | 模块导入导出 | 备份恢复 |
| --- | --- | --- |
| 目的 | 分享、传播一组优质题目 | 保护并恢复用户自己的全部数据 |
| 数据范围 | 用户选择的单个模块 | 全部数据库数据、图片和个人记录 |
| 写入方式 | 合并式新增一个模块 | 全量覆盖当前数据 |
| 原有数据 | 不修改、不删除 | 恢复前先备份，然后整体替换 |
| 复习进度 | 不导出，导入后从 0 开始 | 完整保留 |
| 本机 ID 和题号 | 导入时重新生成 | 恢复时尽量原样还原 |
| 文件扩展名 | `.qsm` | `.qsbk` |
| 文件格式标识 | `qishua_module` | `qishua_backup` |

模块导入服务必须拒绝 `.qsbk` 备份包；备份恢复服务也必须拒绝 `.qsm` 模块包。两套流程不可通过改扩展名互相绕过。

## 3. V1 范围与关键决策

### 3.1 V1 支持

- 系统模块、自定义模块均可导出。
- 一次只导出一个模块，导出该模块当前包含的全部错题。
- 导入前展示题包预览，用户确认后才写入本地。
- 导入后始终创建一个新的自定义模块，不合并到现有系统模块或自定义模块。
- 题目、我的做法、答案/解析的文字和图片可以随包分享。
- 标签和题包内部的错题关联可以随包分享。
- 作者昵称和模块简介作为可选的分享信息。
- 同一个 `packageId` 在同一设备上只允许导入一次。
- 导入完成后可以像普通自定义模块一样编辑、停用和再次导出。

### 3.2 V1 不支持

- 不导出多个模块组成的合集。
- 不选择模块内的部分题目导出。
- 不把题目合并进已有模块。
- 不同步作者后续修改，不做题包在线更新。
- 不做题包市场、下载链接、二维码、账号、关注、评分或评论。
- 不保留导出者的七刷记录、掌握状态、复做照片、语音讲解和个人浏览状态。
- 不允许直接点击系统文件自动唤起 App；V1 从 App 内的文件选择器导入。
- 不校验作者真实身份，不提供数字签名或版权认证。

### 3.3 为什么导入后必须新建自定义模块

- 避免把别人的内容静默混入用户已有模块。
- 避免系统模块名称、永久 ID、题号发生冲突。
- 用户可以清楚识别、查看或停用整个导入题包。
- 为未来的版本更新、来源追踪和重复导入检测保留边界。

即使导出的来源是系统模块“函数”，导入后也要创建新的自定义模块，例如“函数（导入）”，不能写入本机固定的系统模块 A。

## 4. 用户流程

### 4.1 导出流程

1. 用户在模块菜单中选择“导出题包”。
2. App 扫描模块内容并展示导出预览：模块名称、题目数、图片数、作者昵称、简介和警告。
3. 用户确认自己有权分享这些内容。
4. App 校验数据和图片，生成 `.qsm` 文件。
5. App 打开系统分享面板，用户可发送到微信、网盘或保存到文件。
6. 分享取消只结束分享动作，不删除本地模块，也不改变任何题目。

空模块不可导出。任一题目缺少有效的题目图片时不可导出；可选的做法图或答案图缺失时应在预览中提示，并在用户确认后忽略缺失文件。

### 4.2 导入流程

1. 用户在 App 内选择“导入题包”。
2. App 通过系统文件选择器选择 `.qsm` 文件，并先复制到独立临时目录。
3. App 校验文件格式、版本、目录结构、数据约束和图片完整性。
4. App 展示只读预览：题包名称、作者、简介、创建时间、题目数、图片数、文件大小和风险提示。
5. 用户点击“导入为新模块”。
6. App 生成新的本机模块 ID、显示代码、错题 ID、图片 ID、关系 ID 和题号。
7. App 复制图片，并在单个数据库事务中写入模块、错题、标签、关系、图片记录和来源记录。
8. 导入成功后进入新模块；失败则清理本次产生的文件和数据库记录。

### 4.3 名称冲突

模块名称在当前数据库中唯一。导入时按以下顺序生成本地名称：

1. 原名称未占用：使用原名称。
2. 原名称已占用：使用“原名称（导入）”。
3. 仍被占用：依次使用“原名称（导入 2）”“原名称（导入 3）”等。

题包中的原始模块名称必须保存在导入来源记录中，本地改名不应丢失来源信息。

## 5. 数据范围

### 5.1 导出的共享内容

| 当前数据 | 模块包中的表达 | 导入规则 |
| --- | --- | --- |
| 模块名称、图标、颜色 | `module` 元数据 | 用于创建新的自定义模块 |
| `subject` | 题目字段 | V1 只接受 `math` |
| `title` | 题目字段 | 保留 |
| `difficulty` | 题目字段 | 保留，限制为 1-5 |
| `note`、`note_highlights` | 题目字段 | 保留并校验高亮区间 |
| `my_solution_text` | 题目字段 | 保留 |
| `answer_text` | 题目字段 | 保留 |
| 错因 | 稳定内置键或显示名称 | 按名称/内置键映射，不直接复用本机自定义 ID |
| `mistake_tags` | 每题标签数组 | 生成新的标签 ID |
| 题目/做法/答案图片 | 包内相对路径 | 复制到新错题目录并生成新图片 ID |
| 模块内部的错题关联 | 包内题目键之间的关系 | 生成新关系 ID，导入为 `manual` 来源 |

### 5.2 明确不导出的个人状态

- `mistakes.id`
- `modules.id`、`modules.display_code`、`modules.custom_no`
- `mistakes.module_id`、`mistakes.question_no`
- `review_count`、`status`
- `next_review_at`、`last_review_at`、`last_review_result`
- `is_pinned`、`last_viewed_at`
- `review_records` 全部字段
- `review_solution` 图片
- 复做语音及其元数据
- 今日复习卷和复习卷条目
- 原设备图片绝对 URI
- 原记录 ID、创建时间和更新时间
- App 设置、日志、备份历史及其他模块内容

### 5.3 导入后的个人状态

每道导入错题统一设置为：

```text
status = collected
review_count = 0
next_review_at = null
last_review_at = null
last_review_result = null
is_pinned = false
last_viewed_at = null
```

导入不会自动“加入七刷”。用户需要在自己的设备上明确执行加入七刷操作。

### 5.4 错因映射

- 内置错因使用稳定键，例如 `builtin:reason:careless`，导入时映射为本机对应内置 ID。
- 自定义错因在包内只携带名称，不携带导出设备的数据库 ID。
- 导入时若本机已有同名自定义错因，可以关联本机 ID。
- 本机没有同名自定义错因时，不静默创建全局自定义错因；仅将名称保存在兼容展示字段 `error_reason` 中。
- 多个错因的兼容展示文本按包内顺序使用“、”连接；能成功映射的稳定 ID 写入 `error_reason_ids`。

### 5.5 题号规则

- 包内使用 `itemId` 和 `position` 表达题目身份与顺序，不使用导出设备的显示编号。
- 新模块的题号按 `position` 从 1 连续分配。
- `module_question_counters.last_question_no` 在导入成功后等于导入题目数。
- 当前单模块题号上限为 999，因此 V1 题包最多包含 999 道题。
- 包内 `position` 必须从 1 开始连续且不可重复。

## 6. 文件协议

### 6.1 文件名与扩展名

- 扩展名：`.qsm`，含义为 Qishua Module。
- 建议文件名：`qishua-module-{安全模块名}-{YYYYMMDD-HHmmss}.qsm`。
- 示例：`qishua-module-圆锥曲线精选-20260808-213045.qsm`。
- 文件本质为 ZIP 容器；分享时 V1 可使用 `application/octet-stream`。
- 文件名只用于展示，不能作为包类型、作者或唯一性的判断依据。

### 6.2 包内目录

```text
qishua-module-圆锥曲线精选-20260808-213045.qsm
├─ manifest.json
├─ module.json
└─ images/
   ├─ Q001/
   │  ├─ question_001.jpg
   │  └─ answer_001.jpg
   └─ Q002/
      ├─ question_001.jpg
      └─ my_solution_001.jpg
```

所有引用必须使用 `/` 分隔的包内相对路径。禁止绝对路径、反斜杠、空路径、`..`、重复路径和大小写冲突路径。

### 6.3 `manifest.json`

示例：

```json
{
  "format": "qishua_module",
  "formatVersion": 1,
  "packageId": "PKG-0198f28e-45ec-7bf1-b5f2-88da9e83240d",
  "contentVersion": 1,
  "appName": "七刷错题本",
  "appVersion": "1.0.0",
  "createdAt": "2026-08-08T21:30:45.123+08:00",
  "creator": {
    "displayName": "小七"
  },
  "module": {
    "name": "圆锥曲线精选",
    "description": "高三二轮复习中的典型错题",
    "subject": "math",
    "icon": "label",
    "color": "#34C759"
  },
  "counts": {
    "questions": 42,
    "images": 96,
    "relations": 8
  },
  "warnings": []
}
```

字段约束：

- `format` 固定为 `qishua_module`。
- `formatVersion` 控制文件协议兼容性，V1 只接受 `1`。
- `packageId` 是本次不可变题包的全局标识，用于阻止同一个包重复导入。
- `contentVersion` 为未来题包更新预留；V1 固定为 `1`。
- `creator.displayName` 可空，不代表经过身份认证。
- `module.name` 必填；`description` 可空。
- `module.subject` V1 固定为 `math`。
- `counts` 必须与 `module.json` 和包内实际文件一致。
- `warnings` 只保存创建题包时的非致命提示，不得用于掩盖缺失的必需内容。

V1 每次导出都生成新的不可变 `packageId`。将来如果增加“发布新版本”功能，再复用原 `packageId` 并递增 `contentVersion`；V1 不推测或自动合并版本。

### 6.4 `module.json`

示例：

```json
{
  "questions": [
    {
      "itemId": "Q001",
      "position": 1,
      "subject": "math",
      "title": "椭圆离心率范围",
      "difficulty": 4,
      "errorReasons": [
        {
          "kind": "builtin",
          "key": "builtin:reason:case-missing",
          "name": "分类讨论遗漏"
        }
      ],
      "note": "先确认焦点所在的坐标轴。",
      "noteHighlights": [
        {
          "start": 0,
          "end": 8,
          "color": "yellow"
        }
      ],
      "mySolutionText": null,
      "answerText": "分类讨论后分别代入离心率公式。",
      "tags": ["椭圆", "离心率", "分类讨论"],
      "images": [
        {
          "assetId": "ASSET001",
          "type": "question",
          "sortOrder": 0,
          "relativePath": "images/Q001/question_001.jpg"
        },
        {
          "assetId": "ASSET002",
          "type": "answer",
          "sortOrder": 0,
          "relativePath": "images/Q001/answer_001.jpg"
        }
      ]
    }
  ],
  "relations": [
    {
      "sourceItemId": "Q001",
      "targetItemId": "Q002"
    }
  ]
}
```

约束：

- `itemId` 仅在当前题包内唯一，建议按 `Q001-Q999` 生成。
- `assetId` 仅在当前题包内唯一。
- 图片类型只允许 `question`、`my_solution`、`answer`。
- 每道题至少有一张 `question` 图片。
- `tags` 导入前按现有标签归一化规则去重。
- `relations` 两端必须都存在于当前包，不能自关联或重复。
- 关系的原始 `system/manual` 来源不进入题包；包内明确保存的关系导入后统一视为 `manual`。
- 所有文本长度、难度、高亮范围和图片排序必须按当前数据契约校验。

## 7. 导出规则

### 7.1 数据收集

- 页面只提交待导出的本机 `moduleId` 和用户填写的分享信息。
- Service 负责编排，Repository 负责查询模块、错题、标签、关系和图片记录。
- 错题按 `question_no ASC, created_at ASC, id ASC` 稳定排序，再生成连续 `position`。
- 只收集两端都属于本次模块的错题关系。
- 不把数据库行直接序列化进文件，必须显式映射为模块包模型。

### 7.2 图片处理

- 模块包不得保存原始绝对 URI。
- 图片文件名和相对路径由导出服务重新生成。
- 导出前检查每个引用文件真实存在。
- 题目图片缺失属于致命错误，停止导出。
- 做法图或答案图缺失属于非致命警告，用户确认后从包中忽略对应记录。
- 分享前应去除 EXIF、GPS 和其他可能包含设备或位置信息的元数据。
- 不应为导出修改 App 中原有图片；脱敏后的副本只写入临时打包目录。

### 7.3 一致性

- `manifest.json`、`module.json` 和图片必须先写入独立临时目录。
- 完成数量复核后再生成最终 `.qsm` 文件。
- 导出失败时删除临时文件，不修改数据库和原模块。
- 导出成功只代表文件生成成功；用户取消系统分享不算数据错误。

## 8. 导入校验与安全规则

模块包来自其他用户，应按不可信输入处理。

### 8.1 写入前校验顺序

1. 校验扩展名和实际 ZIP 容器。
2. 只读取受限大小的 `manifest.json`，校验 `format` 和 `formatVersion`。
3. 检查 `packageId` 是否已经导入。
4. 校验 ZIP 条目路径，拒绝路径穿越、绝对路径、重复条目和符号链接。
5. 校验 `module.json` 结构、字段类型、长度、枚举和数量。
6. 校验每个图片引用只出现一次，并且对应文件存在。
7. 校验清单数量与实际数据一致。
8. 校验本机仍可创建新的自定义模块和容纳全部题目。
9. 全部通过后才能展示“确认导入”按钮。

### 8.2 建议的 V1 资源上限

这些值应在实现时集中定义为常量，并在真机测试后最终确认：

- 单包最多 999 道题。
- 压缩文件最大 500 MB。
- 解压后总大小最大 1 GB。
- `manifest.json` 最大 1 MB。
- `module.json` 最大 10 MB。
- 单张图片最大 20 MB。
- 图片条目最多 5000 个。

超过限制应直接拒绝，不能尝试完整解压，以避免压缩炸弹、内存耗尽和存储空间耗尽。

### 8.3 重复导入

- V1 以 `packageId` 作为重复判断依据。
- 已存在相同 `packageId` 时展示已导入模块名称和导入时间，并阻止再次导入。
- V1 不提供“覆盖”“合并”或“再导入一份”。用户若确实需要副本，可以先由导出方生成一个新的题包。
- 不同 `packageId` 但内容相同的两个文件，V1 可能被分别导入；内容指纹去重留待后续版本。

## 9. 本地数据库设计建议

为支持来源追踪和重复导入，后续实现建议新增两张表。真正修改 schema 前必须先把最终字段写入 `docs/data_contract.md` 并提升 `DATABASE_VERSION`。

### 9.1 `module_imports`

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY | 本次本机导入记录 ID |
| `package_id` | TEXT NOT NULL UNIQUE | 题包全局标识，用于去重 |
| `content_version` | INTEGER NOT NULL | 题包内容版本，V1 为 1 |
| `module_id` | INTEGER NOT NULL UNIQUE, FK | 导入后创建的本机自定义模块 |
| `source_module_name` | TEXT NOT NULL | 包内原始模块名 |
| `description` | TEXT | 题包简介 |
| `creator_name` | TEXT | 作者昵称，不代表已认证 |
| `package_created_at` | TEXT NOT NULL | 题包创建时间 |
| `imported_at` | TEXT NOT NULL | 本机导入完成时间 |

### 9.2 `module_import_items`

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| `import_id` | TEXT NOT NULL, FK | 对应 `module_imports.id` |
| `item_id` | TEXT NOT NULL | 包内稳定题目键 |
| `mistake_id` | TEXT NOT NULL UNIQUE, FK | 导入后生成的本机错题 ID |
| `position` | INTEGER NOT NULL | 包内原始顺序 |

建议联合主键为 `(import_id, item_id)`。删除错题时可级联删除对应 item 映射；自定义模块采用停用语义时，导入来源记录继续保留。

这两张表只记录题包来源，不保存个人复习状态，也不替代 `modules`、`mistakes` 和 `mistake_images`。

## 10. 原子性与失败清理

文件系统和 SQLite 不能组成真正的跨系统事务，导入流程应使用“先准备文件、再提交数据库、失败补偿”的策略：

1. 在临时目录完成解压、校验和图片脱离包路径的准备。
2. 预先生成本机模块 ID、错题 ID、图片 ID、关系 ID 和最终图片 URI。
3. 将图片复制到全新的错题目录；任何复制失败都停止，不写数据库。
4. 在一个 SQLite 事务中写入模块、计数器、错题、图片记录、标签、关系和导入来源记录。
5. 数据库事务失败时，删除本次新建的所有错题图片目录。
6. 数据库提交成功后，删除临时目录并做数量复核。

当前服务实现中，用户确认导入后会重新只读解析原 `.qsm`，先检查 `packageId`，再把图片按 `assetId` 平铺写入本次专属缓存目录。暂存时会再次校验源文件大小、ZIP 条目集合、路径、单条目与总解压大小、图片尺寸及 JPEG 首尾签名，避免直接信任预览阶段的路径或元数据。数据库事务内部会再次检查 `packageId` 唯一性，以覆盖两个导入请求并发通过事务外预检查的情况。

由于新 ID 对应的图片目录此前不存在，补偿清理不会触碰用户原有图片。若 App 在“图片已复制、数据库未提交”之间崩溃，可能留下孤立文件；现有存储维护流程应在下次运行时识别并清理这种无数据库引用的目录。

任何失败都必须满足：

- 原有模块、错题、题号和图片不变。
- 不留下部分导入的模块或题目。
- 错误信息说明失败阶段，但日志不得记录题目正文、答案正文或完整本机路径。

## 11. 分层与建议目录

后续实现建议使用独立的模块传输目录，不把分享逻辑塞进 `BackupService`：

```text
src/models/ModulePackage.ts
src/services/moduleTransfer/ModuleExportService.ts
src/services/moduleTransfer/ModuleImportPreviewService.ts
src/services/moduleTransfer/ModuleImportStagingService.ts
src/services/moduleTransfer/ModuleImportExecutionService.ts
src/services/moduleTransfer/ModulePackageValidator.ts
src/repositories/ModuleImportRepository.ts
app/module-import.tsx
app/module-transfer/export.tsx
```

职责约束：

- 页面层只处理选择、预览、确认、进度和结果，不写 SQL、不直接操作文件。
- `ModuleExportService` 负责数据映射、脱敏、打包和分享编排。
- `ModuleImportPreviewService` 负责只读解析和预览，不写数据库或文件。
- `ModuleImportStagingService` 负责将校验过的图片安全解压到独立临时目录并清理。
- `ModuleImportExecutionService` 负责重复检测、ID 映射、图片落盘、单事务写入和失败补偿。
- `ModulePackageValidator` 只做纯校验，不产生数据库或文件系统副作用。
- Repository 层负责全部 SQL，并为模块、标签和来源记录提供事务内写入能力。
- 图片最终仍进入 `ImageService`/图片存储层约定的错题目录，不建立第二套长期图片目录。

## 12. UI 信息架构

“题包导入/导出”必须与“备份与恢复”分成不同入口和说明。

建议入口：

- 模块菜单：`导出题包`。
- 题库页操作区或设置页“题包”分组：`从文件导入题包`。
- 备份分组仍只显示备份导出和恢复，不出现题包按钮。

导入预览至少展示：

- 模块名称、作者昵称、简介。
- 题目数量、题目图/做法图/答案图数量。
- 文件创建时间、文件大小。
- “导入后复习进度从 0 开始”的明确提示。
- “作者昵称未经平台认证”的提示。
- 包内警告、版本不兼容或重复导入状态。

## 13. 隐私与内容责任

- 导出确认页应提醒用户检查图片、备注、答案中是否含姓名、学校、二维码等个人信息。
- 导出图片必须移除可识别的 EXIF/GPS 元数据。
- 包内不保存原设备绝对路径、设备型号、日志、数据库 ID 和复习历史。
- 作者昵称为用户自行填写的展示文字，不构成身份认证。
- V1 可要求用户勾选“我确认有权分享这些内容”；版权授权、举报和内容审核属于未来在线生态范围。

## 14. 验收标准

### 14.1 正常场景

- 可从系统模块导出一个包含题目、做法、答案、标签和内部关联的 `.qsm` 文件。
- 可从自定义模块导出并在另一台设备导入。
- 导入后生成新的自定义模块和本机显示代码。
- 导入题目顺序正确，题号从 1 连续开始。
- 题目、做法、答案图片均可打开，文本与高亮正常。
- 标签保留，题包内部关联仍可查看。
- 所有题目均为 `collected`，复习次数为 0，且不自动出现在今日七刷任务中。
- 导入不会改变导入前已有模块、错题、计数器和图片。

### 14.2 冲突与异常

- 模块同名时自动生成不冲突的“（导入）”名称。
- 同一 `packageId` 第二次导入时被阻止。
- `.qsbk`、普通 ZIP、伪造扩展名和不支持的协议版本均被拒绝。
- 缺少 `manifest.json`、`module.json` 或任一必需题目图片时被拒绝。
- 包内路径含 `..`、绝对路径或重复路径时被拒绝。
- 超过题数、图片数或解压大小限制时被拒绝。
- 图片复制失败或数据库写入失败后，不存在部分导入数据。
- 用户取消文件选择、预览或确认时不产生任何数据修改。

### 14.3 与备份共存

- 模块包不能进入备份恢复预览。
- 备份包不能进入模块导入预览。
- 完整备份应包含导入后产生的普通模块、错题、图片，以及新增的题包来源表。
- 从完整备份恢复后，重复导入检测仍然有效。

2. 更新 `docs/data_contract.md`，新增来源表并完成数据库迁移。
