# 七刷错题本 - 验收测试清单（MVP）

适用环境：Windows + VSCode + Codex，使用 Web 预览、Android 真机或 Android 模拟器进行验收。

## 1. 项目启动验收
- [ ] `npm install` 可以成功
- [ ] `npx expo start` 可以启动
- [ ] 按 `w` 可以打开 Web 预览
- [ ] `npx expo run:android` 可以安装到 Android 真机或模拟器
- [ ] App 可以正常打开

## 2. 页面骨架验收
- [ ] 首页可以打开
- [ ] 错题列表页可以打开
- [ ] 录入错题页可以打开
- [ ] 设置页可以打开
- [ ] 底部 Tab 可以正常切换
- [ ] 页面没有明显红屏报错

## 3. 拍照功能验收（后续实现后使用）
- [ ] 点击拍照按钮可以打开相机
- [ ] 用户取消拍照不会崩溃
- [ ] 拍照后页面可以显示图片
- [ ] 重启 App 后图片仍然存在
- [ ] 保存的是持久化 uri，不是临时 uri

## 4. SQLite 验收（后续实现后使用）
- [ ] 数据库可以初始化
- [ ] 可以创建一条错题
- [ ] 可以查询错题列表
- [ ] 关闭 App 后重新打开，错题仍然存在

## 5. 录入错题验收（后续实现后使用）
- [ ] 没有题目照片不能保存
- [ ] 保存成功后有提示
- [ ] 保存成功后错题出现在列表
- [ ] 保存成功后可以进入详情页

## 6. 7 次重做验收（后续实现后使用）
- [ ] 新错题显示 `0/7`
- [ ] 完成一次后变成 `1/7`
- [ ] 每次重做生成 `review_record`
- [ ] 做满 7 次后状态变成 `mastered`
- [ ] 已掌握错题不再出现在今日待复习

## 7. Codex 每轮修改验收
- [ ] 是否只完成本轮任务
- [ ] 是否修改了无关文件
- [ ] 是否破坏已有页面
- [ ] 是否有 TypeScript 报错
- [ ] 是否有控制台异常
- [ ] 是否更新了必要文档

## 9. 录入草稿体验验收补充（第5步）

- [ ] 保存中按钮显示“保存中...”，且不可重复点击。
- [ ] 校验失败时页面可见错误文案（至少包含：请先拍题目照片、请选择模块、难度不合法）。
- [ ] 保存成功后提示“错题已加入 7 刷计划”，并显示 mistakeId。
- [ ] 保存成功后草稿重置：新 draftId、图片预览清空、模块/错因/难度恢复默认、标题/备注清空。
- [ ] 删除图片失败时有提示且页面不崩溃。
- [ ] 风险记录：未保存草稿图片可能残留在本地目录，后续可增加“放弃草稿时删除 draftId 目录”能力。

## 10. 第5步录入错题联合验收（5-G）

- [ ] 打开新增页。
- [ ] 拍题目照片。
- [ ] 可选拍做法照片。
- [ ] 可选拍答案照片。
- [ ] 选择模块。
- [ ] 选择错因。
- [ ] 选择难度。
- [ ] 点击保存。
- [ ] 打开 `/dev/db`。
- [ ] 点击“查询最近10条错题”。
- [ ] 确认 `mistakes` 有记录（含 id/module/difficulty/question_image_uri 等字段）。
- [ ] 在该记录上点击“查看该错题图片记录”。
- [ ] 确认 `mistake_images` 有图片记录（type/uri/created_at）。
- [ ] 确认每条图片 `exists = true`。
- [ ] 关闭 App 后重启。
- [ ] 再次打开 `/dev/db`。
- [ ] 数据仍然存在。

## 11. 第5步统一验收清单（5-H）

### 11.1 新增页交互验收
- [ ] 打开新增页后可看到草稿 ID。
- [ ] 可选择模块。
- [ ] 可选择错因（可不选）。
- [ ] 可选择难度（默认 3）。
- [ ] 可拍题目照片、我的做法、答案/解析。
- [ ] 可从相册选择上述三类图片。
- [ ] 已选图片可预览。
- [ ] 可删除已选图片，失败时有提示且页面不崩溃。

### 11.2 保存链路验收
- [ ] 未拍题目照片时，保存被拦截并提示“请先拍题目照片”。
- [ ] 未选择模块时，保存被拦截并提示“请选择模块”。
- [ ] 难度非法时，保存被拦截并提示“难度不合法”。
- [ ] 保存中按钮禁用，文案为“保存中...”，不可重复点击。
- [ ] 保存成功提示“错题已加入 7 刷计划”，并可看到 `mistakeId`。
- [ ] 保存成功后草稿重置：新 `draftId`、图片清空、模块/错因/难度恢复默认、标题/备注清空。
- [ ] 保存失败后保留草稿与图片，便于修正后重试。

### 11.3 /dev/db 联合验收
- [ ] 在新增页保存一条错题后，打开 `/dev/db`。
- [ ] 点击“查询最近10条错题”，确认 `mistakes` 记录存在。
- [ ] 校验关键字段：`id/module/difficulty/question_image_uri/review_count/status/created_at`。
- [ ] 确认 `id` 与新增页保存时使用的 `draftId` 一致。
- [ ] 点击“查看该错题图片记录”，确认 `mistake_images` 中 `question/my_solution/answer` 类型正确。
- [ ] 对每条图片记录检查 `exists = true`，并显示 `size`（可为空）。

### 11.4 重启持久化验收
- [ ] 彻底关闭 App。
- [ ] 重新打开 App，再次进入 `/dev/db` 查询同一记录。
- [ ] `mistakes` 与 `mistake_images` 仍存在，图片文件仍为 `exists = true`。

### 11.5 当前已知风险（待后续阶段）
- [ ] 用户未保存直接离开新增页时，`draftId` 对应图片目录可能残留。
- [ ] 后续可增加“放弃草稿时清理 draft 目录”能力（不影响第5步闭环验收）。

## 12. 第6步错题列表验收清单（6-D ~ 6-H）

### 12.1 题库页真实列表
- [ ] 打开题库页后可读取 SQLite 真实错题。
- [ ] 列表卡片显示模块、标题、进度、状态标签。
- [ ] 有 `thumbnailUri` 时显示缩略图；无图或加载失败显示占位。
- [ ] 点击卡片跳转 `/mistake/[id]`。

### 12.2 搜索与筛选
- [ ] 分段筛选可切换：全部 / 待复做 / 已七刷。
- [ ] 搜索可命中 `title/module/error_reason/note`。
- [ ] 搜索 + 筛选组合有效。
- [ ] 搜索为空时恢复当前分段的全量数据。

### 12.3 状态与容错
- [ ] 首次加载显示 loading，不出现红屏。
- [ ] 空库显示空状态，不展示假数据。
- [ ] 搜索无结果显示“没有找到相关错题”。
- [ ] 待复做为空显示“今天没有待复做错题”。
- [ ] 已七刷为空显示“还没有完成七刷的错题”。
- [ ] 错误态显示重试按钮，点击可重新拉取。
- [ ] 支持下拉刷新。

### 12.4 首页轻量真实接入（6-G）
- [ ] 今日待复做、总错题、已七刷、完成率来自真实数据库。
- [ ] 优先复做显示真实 due 第1条，若无则显示空状态。
- [ ] 错题队列显示真实前几条，若无则显示空状态。
- [ ] 从新增页保存后返回首页，统计与队列可刷新。

### 12.5 稳定性
- [ ] FlatList 的 key 使用 `item.id`，不使用 index。
- [ ] 列表为空、图片失败、查询失败均不崩溃。

## 13. 第8-B 服务层验收点

- [ ] `mastered` 状态调用 `completeReview` 被拒绝。
- [ ] `archived` 状态调用 `completeReview` 被拒绝。
- [ ] `reviewIndex` 与 `review_count + 1` 不一致时提交被拒绝。
- [ ] `solutionImageUri` 为空时提交被拒绝。
- [ ] 第 7 刷提交后 `status = mastered` 且 `next_review_at = null`。
- [ ] 事务失败时尝试清理本次复做图片孤儿文件（仅目标 `solutionImageUri`）。
## 14. 第8-C 复做页验收点

- [ ] 从详情页点击“开始第 N 刷”进入 /review/[id]。
- [ ] 复做页显示真实错题信息（标题、模块、当前进度、本次刷次）。
- [ ] 复做页只展示题目图片，不展示答案图片。
- [ ] 未拍“本次复做照片”时，点击提交会提示“请先拍本次复做照片”。
- [ ] 拍照成功后显示复做照片预览，并可“重新拍照”与“删除”。
- [ ] 提交中按钮显示“保存中...”，且提交/拍照/删除均不可重复触发。
- [ ] 提交成功后返回详情页（/mistake/[id]）并看到进度更新。
## 15. 第8-D 联动刷新与 Android 回归验收点

- [ ] 在复做页完成一次提交后，返回详情页可看到 `review_count` 立即更新。
- [ ] 详情页 `ProgressDots`、`statusLabel`、复做按钮文案与当前状态一致。
- [ ] 详情页可看到“复做记录”模块；无记录显示“还没有复做记录”。
- [ ] 详情页复做记录按刷次升序展示，包含第 N 刷、created_at、result。
- [ ] 复做记录存在 `solution_image_uri` 时可见缩略图或“已保存照片”。
- [ ] 返回题库页后，卡片进度与状态标签更新。
- [ ] 题库页“待复做”不包含 `mastered` 错题；“已七刷”能看到该错题。
- [ ] 返回首页后，今日待复做、已七刷、完成率、优先复做、错题队列同步更新。
- [ ] 完成第 7 刷后详情页按钮禁用并显示“已完成七刷”。
- [ ] 完成第 7 刷后重启 App，详情/题库/首页状态仍一致。
## 16. 第8-E MVP 核心闭环最终验收清单

### 16.1 录入错题
- [ ] 新增页可拍题目照片。
- [ ] 可选择模块、错因、难度。
- [ ] 点击保存后写入 `mistakes` 与 `mistake_images`。
- [ ] `mistakes.question_image_uri` 有值。
- [ ] 新记录 `review_count = 0`。
- [ ] 新记录 `status = active`。
- [ ] 新记录 `next_review_at` 为当天日期。

### 16.2 题库展示
- [ ] 题库页显示真实错题，卡片进度显示 `0/7`、`1/7` 等。
- [ ] 全部 / 待复做 / 已七刷筛选正常。
- [ ] 搜索可命中标题、模块、错因、备注。
- [ ] 点击卡片进入真实详情页。
- [ ] 空状态与图片加载失败不崩溃。

### 16.3 详情查看
- [ ] 详情页按真实 `id` 读取数据。
- [ ] 显示标题、模块、错因、难度、进度。
- [ ] 显示题目/做法/答案图片（按存在情况兜底）。
- [ ] 显示复做记录列表（无记录显示空文案）。
- [ ] `active` 显示“开始第 N 刷”；`mastered` 显示“已完成七刷”；`archived` 不可复做。

### 16.4 复做提交流程
- [ ] 从详情页进入复做页。
- [ ] 复做页显示真实题目。
- [ ] 未拍复做照片不可提交。
- [ ] 拍照后可预览；提交中按钮 disabled。
- [ ] 提交成功返回详情页；失败保留复做照片。
- [ ] 重复点击不会导致 `review_count` 连续增加。
- [ ] 页面层不直接写 SQL，仅通过 `CompleteReviewService` 提交。

### 16.5 数据一致性与 7/7
- [ ] 每次复做：`review_records +1`。
- [ ] 每次复做：`mistake_images(type=review_solution) +1`。
- [ ] 每次复做：`mistakes.review_count +1`，`updated_at` 更新，`next_review_at` 按规则更新。
- [ ] 第 7 刷后：`status = mastered`，`next_review_at = null`。
- [ ] `mastered` / `archived` 状态服务层拒绝继续复做。
- [ ] `reviewIndex` 不匹配服务层拒绝提交。

### 16.6 联动刷新与重启持久化
- [ ] 复做后详情页、题库页、首页均显示最新数据。
- [ ] 7/7 后题库“待复做”不再显示该题，“已七刷”可见。
- [ ] 7/7 后首页待复做统计不再包含该题。
- [ ] 关闭并重启 App 后，详情/题库/首页状态与图片仍一致。
