# 七刷错题本 Android 真机人工测试清单（第9步）

本文用于 Android 真机手工测试，不是自动化测试脚本。  
目标是帮助你按固定步骤回归 MVP 核心闭环，并在出问题时留下可复现证据。

## 一、测试前准备

1. 确认 Android 真机已通过 USB 连接电脑，并开启开发者模式与 USB 调试。
2. 在项目根目录执行：
   - `adb devices`
3. 确认设备状态为 `device`（不是 `offline` / `unauthorized`）。
4. 启动 App（任选其一）：
   - `npm run android`
   - `npx expo run:android`
5. 确认 App 可以正常打开到首页。
6. 确认终端可以看到前端日志（`Logger.info / warn / error`）。
7. 如需查看原生日志，使用：
   - `adb logcat`

## 二、基础启动测试

- [ ] App 能启动，不闪退
- [ ] 首页能打开
- [ ] 新增页能打开
- [ ] 题库页能打开
- [ ] 可从题库进入详情页
- [ ] 可从详情页进入复做页
- [ ] Android 返回键行为合理（逐级返回，不出现死循环或黑屏）

## 三、录入错题测试

步骤：

1. 打开新增页。
2. 拍题目照片。
3. 选择模块。
4. 选择错因。
5. 选择难度。
6. 可选：拍“我的做法”。
7. 可选：拍“答案”。
8. 点击保存。
9. 预期结果：
   - 保存成功提示出现。
   - 自动返回或可进入题库看到新错题。
   - 默认新错题 `review_count = 0`，`status = collected`，`next_review_at = null`。
   - 开启“同时加入 7 刷”后，新错题 `status = active`，当天可复做。
10. 如果失败，记录：
   - 操作步骤
   - 页面报错文案
   - 终端日志片段
   - `adb logcat` 关键片段（如有）
   - 截图/录屏

## 四、数据持久化测试

步骤：

1. 新增并保存一条错题。
2. 完全关闭 App。
3. 在最近任务里划掉 App（杀后台进程）。
4. 重新打开 App。
5. 打开题库页。
6. 确认该错题仍存在。
7. 打开该错题详情页。
8. 确认题目图片（及可选图片）仍可显示。

## 五、复做流程测试

步骤：

1. 打开某条错题详情页。
2. 点击“开始第 1 刷”。
3. 不拍照直接提交。
4. 预期：不能提交，并有明确提示（需先拍本次复做照片）。
5. 拍复做照片。
6. 点击提交。
7. 预期：返回详情页，进度变为 `1/7`。
8. 重复复做直到 `7/7`。
9. 预期：
   - `status = mastered`
   - 详情页复做按钮禁用（不可继续复做）

## 六、重复点击测试

测试项：

- [ ] 保存错题按钮连续快速点击
- [ ] 复做提交按钮连续快速点击
- [ ] 拍照后快速“删除/提交”交替点击
- [ ] Android 返回键连续快速点击

预期：

- 不应重复创建错题
- 不应导致 `review_count` 连续多次增加
- 页面不应红屏、不应崩溃

## 七、图片异常测试

测试项：

- [ ] 拍照后在系统相机内取消
- [ ] 相册选择后取消（如当前页面支持相册）
- [ ] 删除已拍图片后重新拍照
- [ ] 图片加载失败时显示占位/错误提示，不崩溃
- [ ] App 重启后图片仍存在

## 八、筛选搜索测试

测试项：

- [ ] 题库筛选“全部”正确
- [ ] 题库筛选“待复做”正确
- [ ] 题库筛选“已七刷”正确
- [ ] 搜索模块关键词有效
- [ ] 搜索错因关键词有效
- [ ] 搜索不存在关键词时显示空状态，不崩溃

## 九、7/7 mastered 专项测试

测试项：

- [ ] 同一错题完成 7 次复做
- [ ] 详情页按钮变为禁用状态
- [ ] 题库“已七刷”筛选中可看到该题
- [ ] 题库“待复做”筛选中看不到该题
- [ ] 首页待复做数量正确减少/更新
